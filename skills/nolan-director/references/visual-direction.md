# 对话内的图文解释

默认是文字创作谈话，直接给判断和具体建议。只有创作者要求图，或某项空间/剪辑关系确实难以用文字说明时，才用图帮他看清决定。图不是专业程度的证明，不以每轮有图为目标。镜数、格式和图型随当前难点；小修订可以只聊相关变化。

优先使用运行时的原生内嵌可视化工具。本机原生测试实际出现show_widget，并在对话流显示图示；使用当前工具提供的真实参数，不自造tools权限。将轻量SVG/原生图形放进组件，可画镜头画框、人物/相机俯视位置、视线与运动箭头、剪辑时间带和声音波段。少量CSS够用，不引入框架、外部依赖、导航、网页按钮或页面外壳。直接调用工具展示，不先Write文件，不开Browser，不启动服务器。最后一次show_widget调用完成后，最终回复保留当前请求范围内的完整判断与关键拍法；单镜问题只解释该镜，不能扩大成整场。WorkBuddy可能折叠绘图前的消息，图不能代替最终正文，也不能只剩追问。具体时长的合计、正文、图标保持一致，未定时长用相对节奏。

第一条可见消息先在一个自然段给可用的导演判断，发出之后才读取可视化指南、设计或调用内嵌图形；不说“我先给建议再画图”的流程语。普通场次将机位图、镜头画框和必要时间条集中在一个图块内，尽量一次调用；避免多次工具调用和重复长说明。流程和时间条优先用简洁CSS卡片、箭头与长短条，不逐个推演SVG坐标；空间关系确实需要时才绘制简单SVG。图形代码只实现所需内容，不为了装饰反复重写，不预演整段代码。复杂问题需要时可拆分。图内文字少且清楚；正文镜号与图一致。按顺序说每张图怎样改变观众体验和怎样拍出来。时间条中的秒数是本场试剪设计，不是原片参数。未确认经历/地点标占位，不能用漂亮画面创造客户事实。

用户需要实际画面参考时，再判断是否生图。仅讨论曝光、焦点或材质，可以直接分析已有素材或提出比较方法。需要图片且运行时支持时，实际生成原创概念图并内嵌显示；没有则清楚说明可用表达。不把提示词、路径或网页预览等同已展示图片。生图不能阻塞已有建议。若用本包assets/original-shot-study.png，先确认匹配当前内容；不把旧海岸示例塞给其他场景。

平台没有原生内嵌工具/图片渲染时，不假装已显示；在那一处简短说明实际限制，并给它能显示的图文表达。不要把限制偷偷转成网站交付。普通对话不调用脚本、不创建HTML，不用“详细见预览”的交付语。

画空间图时先以本轮已采用的方案重建位置：人物在哪里、面向哪里，相机在哪里、朝哪里，镜头究竟看见脸、侧面或背面。文字与图必须同一方案；不能把已被作者替换的旧机位直接沿用。仅有主体位置不够，应标出朝向并沿相机视线检查遮挡。

## 仅在明确要导出/保存时
可用scripts/render_shotboard.py生成SVG/HTML作为下载或保存的附件：
python3 <技能目录>/scripts/render_shotboard.py shotboard.json --out <项目输出目录>
字段见assets/shotboard-example.json；室内/街景用room/street，水下用underwater，人物与相机位置按本场给，禁止通用海岸示例替代。脚本是导出备选，不是日常对话绘图路径。即使用户要文件，当前对话仍先给建议及可用内嵌图。用户要求网站时才建设或打开网站。

色彩、手持/稳定、景别和节奏都是本场选择。记忆不自动暖色、现实不自动冷色；回忆不自动模糊，过去的人也可以有清楚的脸和独立动作。根据人物、场景与实拍/生成条件选取，不把类型习惯包装成诺兰的固定方法。
