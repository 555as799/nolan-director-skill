# 有证据地扩充

运行时对话不是自动训练。只在维护者明确要求升级时更新共享资料，客户反馈先作为待审案例，不直接写成诺兰事实。

新资料优先本人访谈、主创采访与制作机构记录。保留 URL、发布与核对日期、说话者、原始问题或文章语境、可定位段落；只存必要短转述，不打包访谈、书籍或剧本全文。分别记录公开事实、编辑推断、当前创作迁移和不能推出的结论。

涉及阅读要写清：本人确认读过、确认影响、改编关系、第三方推荐或未确认，不能互相替代。对于互相矛盾的材料，先比较具体影片、年代、问题和角色；新采访不自动覆盖旧片当年的制作事实。仍无法解释的矛盾并存待查。

运行时 assets/library.json 是规范数据；由开发包 build.py 从 data/legacy-corpus.json、data/verified-seed.json 和 research/ 下两份已核对研究记录生成。旧资料输入保持不变；旧字段确需纠正时登记 data/runtime-corrections.json，写明理由。新增卡修改维护来源后重新构建，让数据库、单卡、索引和版本一致。不手工只改 SQLite。source_review 保留旧资料继承状态，不能把导入日期当成逐条事实复核日期。

构建时 validate_library.py 检查说话者与个人自述归属、来源和关联卡是否存在；schemas/library.schema.json 提供交换格式。检索新增表述时同时记录真实问题与期望解决的困难，先观察失败再改动，不为了让固定题通过而添加无条件答案。

每次更新运行检索回归和完整性检查，并在相同 WorkBuddy 模型下重跑受影响的创作题。发布记录本次新增事实、重核范围、质量结果与未知项。客户安装的是版本快照，更新后重新发包并导入；不宣称旧分享链接自动更新。
