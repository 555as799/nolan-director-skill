# 诺兰创作对话：升级方案与增量样包

调研日期：2026-10-07。样包版本：0.2.0，未合并旧版、未部署、未发布。

产品目标：说话者是诺兰角色，用户与其用第一人称持续讨论创作。用他的公开经历、作品细节、阅读影响和创作判断支持建议。当前修订已纠正早期样包偏向第三人称顾问的定位；经核验的本人自述可在角色中第一人称讲述。入口标注 AI 角色演绎，会话保持沉浸。

建议保留 WorkBuddy 专家作为普通用户入口，用一套可迁移的 Skill 和有出处的知识卡维护核心能力。开放源码是后续的分发选择，不是提升回答质量的必要条件。

本次工作区没有可读取的旧项目文件；分享聊天未返回正文，WorkBuddy 分享页未能读取配置。因此，旧版语气、知识库规模、工具和记忆设置均未核验，不能声称“原有能力已全部保留”或“线上已升级”。本样包供审阅和后续合并，包含 6 张起始经验卡，不能代表完整诺兰知识库。

## 产品判断

| 方案 | 适用对象 | 本项目建议 |
| --- | --- | --- |
| WorkBuddy 专家 | 希望打开链接就开始交流的现有平台用户 | 保留为首要入口；验证分享后的实际体验 |
| 可迁移 Skill | 使用支持 Agent Skills 的工具、愿意安装的人 | 承载方法、表达规则、证据索引和可复用流程 |
| 开源仓库 | 希望检查、贡献、二次开发的人 | 待内容、许可和测试完善后发布；与专家共用一份内容 |
| 独立网页产品 | 需要平台外访问、统一账号、项目管理的人 | 等真实用户需求证明值得承担开发与维护成本后再做 |

“专家”是产品中的角色入口；Skill 是可调用的能力包；是否拥有自主规划、检索、修改和复核的执行循环，要检查实际运行行为。一个 Skill 目录本身不包含模型、运行服务或独立聊天界面。

WorkBuddy 官方把专家称为 Agent 型，其开放平台支持专家绑定 skills。专家分享说明还明确提到接收方召唤的是副本；官方页面没有在这里保证旧副本自动获得后续更新。因此需用接收方账号实测更新传播，发布时显示内容版本，不能默认“一处更新、所有人即时同步”。参见 [专家说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Expert-Center) 和 [专家包规范](https://open.workbuddy.cn/docs/expert)。

## 类似方案中值得采用的做法

| 一手来源 | 已核验做法 | 本项目采用的设计判断 |
| --- | --- | --- |
| [Delphi 知识与训练文档](https://help.delphi.ai/articles/16041852-add-knowledge-train-mind) | 汇集资料、区分内容归属、设置引用链接，并用反馈改进回答 | 分开维护公开经历、外部书籍、用户项目和纠错记录 |
| [ChatHaruhi 论文](https://arxiv.org/abs/2308.09597)及[开源项目](https://github.com/LC1332/Chat-Haruhi-Suzumiya) | 结合角色提示与从剧本提取的记忆来维持角色表现 | 借鉴相关记忆的调用方式；虚构角色实验不能证明真人专家意见准确 |
| [Agent Skills 规范](https://agentskills.io/specification)及[OpenAI Docs](https://developers.openai.com/api/docs/guides/tools-skills) | 将任务指令和配套资源打包，按需加载 | 表达、方法与知识分文件维护，减少重复和无关上下文 |
| [Anthropic 工程说明](https://www.anthropic.com/engineering/building-effective-agents) | 区分预设工作流与模型自主决定步骤的 Agent，建议按需求增加复杂度 | 先做好单专家检索与回答，再根据失败案例增加工具与流程 |

以上是设计依据，未对这些产品做账户内横向实测，也没有证据支持本样包优于它们。

DirectorSKILL 的诺兰文件给出前 90 秒交代规则、固定镜头时长等预设。文件中未为这些限制列出可验证出处，因此应作为仓库作者设计的生成规则评估，不能直接装入知识库并声称它们是诺兰本人的普遍创作准则。

采用方向：保留第一人称对话核心，借鉴人物 Skill 的资料组织，用经过核验的诺兰经历支撑角色；只有用户需要分镜、剪辑表等制作交付时，再参考导演工具类技能。现阶段不引入完整影视生产平台。

## 让“经验”真正进入建议

每张知识卡分开记录：资料事实、出处定位、我们提炼的原则、适用条件、失效条件和可执行练习。不要把影评推断写成导演自述，也不要把用户剧本中的故事混入诺兰履历。

建议建立四种证据类型：本人公开自述、合作者具名回忆、作品直接观察、我们的分析推断。书籍还要区分“本人确认读过”“本人确认影响了某部作品”“研究者认为可作类比”；这三种关系不能互换。

回答时先理解创作困境，再检索相关卡片，检查是否适用，最后给出具体改法。常规回答用一两个真正有关的细节就够了；用户追问时再深入，避免每次都堆片名。资料不足时照样可以给原创建议，但明确这是当前分析。

表达目标：以诺兰角色平静、耐心、具体地交流，围绕观众体验和创作取舍展开，适当用设问推动思考。核验过的本人自述可用“我”转述，新建议用“放到你的故事里，我会……”自然展开。入口标注“诺兰 AI 角色演绎”；会话中不反复打断，直接被问及现实身份时如实回答。来源通常放在末尾或按需展开。文字样包只覆盖措辞和节奏，不代表已经实现声音或语调合成。

## 样包内容与使用

- `skills/nolan-film-mentor/SKILL.md`：可迁移技能入口。连同整个目录交给支持 Skills 的宿主安装或读取；本次没有自动安装到全局目录。
- `skills/nolan-film-mentor/references/voice.md`：表达方式及原创回答示例。
- `skills/nolan-film-mentor/references/knowledge.json`：6 张已打开一手资料核对的起始经验卡。
- `skills/nolan-film-mentor/references/evidence.md`：检索、事实归属和新增资料规则。
- `adapters/workbuddy-addendum.txt`：给现有专家的增量配置文本，需与旧配置合并并接通资料读取。
- `evals/cases.json`：15 道人工验收题及判据，包含第一人称、多轮角色连续性与原创新建议；不是已执行的评测结果。

在能读取工作区的宿主中，可直接要求：“读取 `skills/nolan-film-mentor/SKILL.md`，用它分析这段剧本。”在不能读取目录的宿主中，需要将技能正文和相关参考资料交给其可访问的上下文或知识库。仅粘贴增量文本，不会自动让外部平台获得本机知识卡。

不提供未经验证的 WorkBuddy 可导入 ZIP。正式专家包还需要真实作者信息、头像、平台配置和客户端验证；本次产物是内容样包与适配文本。

## 实施顺序与验收

1. **核对旧版**：导出角色设定、工具列表、知识库目录与代表性回答；备份后逐项列出保留、补充和纠正的内容。现阶段该步骤等待旧配置。
2. **合并小样**：保留已有效的语气和工作方式，将本样包的证据归属、检索和表达规则接入；在同一模型与工具配置下比较旧版和候选版。
3. **扩大知识覆盖**：先补到约 50 张经核验卡，再根据真实问答扩展到 100 张以上。这些是建议目标，不是现有数量。按叙事、表演、剪辑、声音、实拍、合作、预算与阅读影响覆盖，避免单篇采访拆成大量重复条目。
4. **发布双入口**：普通用户使用专家链接；进阶用户安装版本化 Skill。发布同一版知识与指令，记录专家版本和知识版本；测试接收方的资料访问与更新机制。
5. **按证据迭代**：将错误回答整理成纠错卡和回归题；用户建议先作为反馈，核验后才进入事实库。普通聊天、知识更新、偏好记忆和模型微调是不同操作，不宣称聊天会自动训练底层模型。

发布前建议把 15 道烟雾测试扩展到至少 30 道，覆盖已有能力及新场景。每题在相同模型、工具和上下文条件下重复 3 次，匿名交给目标用户评审。先用以下目标验收，再根据实际反馈调整：已观察样本中无编造自述/出处；可核验事实至少 95% 得到所引资料支持；第一人称角色连续性、建议可执行性和自然交流不低于旧版；没有额外安装教程也能完成首个任务。通过有限测试不保证未来零错误。

开源时发布自编指令、结构、原创练习和原创摘要；外部访谈、书籍与影视原文保持独立来源，不把它们自动纳入本项目的开源许可。正式发布前为自有内容确定并添加明确许可证。本样包尚未作为开源发行版发布。
